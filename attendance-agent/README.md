# Branch Attendance Agent — ستاموني

برنامج صغير مستقل بيشتغل على جهاز/سيرفر الفرع، بيتصل بجهاز بصمة ZK المتصل بشبكة الفرع كل فترة معينة،
يسحب البصمات الخام، ويبعتها لسيرفر ستاموني - بديل رفع ملف Excel شهري يدوي (متابعة أقرب للحظية للحضور
والانصراف والتأخيرات المتكررة).

## ⚠️ تنبيه مهم قبل ما تشغّله

الكود ده **اتكتب من بيئة تطوير معزولة من غير وصول لأي جهاز ZK حقيقي أو شبكة فرع فعلية** - اتبنى على أساس
البروتوكول الموثّق لأجهزة ZKTeco/ZKSoftware ومكتبة [`node-zklib`](https://www.npmjs.com/package/node-zklib)
القياسية، لكن **معملناش عليه اختبار فعلي مع جهاز حقيقي**. قبل ما تعتمد عليه في الإنتاج:

1. شغّله أول مرة من `cmd`/`PowerShell` مباشرة (مش كـservice) وراقب اللوج (console) كويس.
2. لو حصل خطأ في `getAttendances()` أو الشكل اللي بيرجع مختلف عن المتوقع، افتح `device-client.js` وحط
   `DEBUG_RAW_LOG=1` في `.env` - هيطبعلك شكل أول سجل خام من الجهاز فعليًا، وعلى أساسه ظبط أسماء الحقول
   في `getRawAttendanceLogs()` (بعض موديلات/نسخ الـfirmware بترجع أسماء حقول شوية مختلفة).
3. تأكد إن أرقام "User ID" المسجلة على الجهاز نفسه بتتطابق حرفيًا مع `device_code` المسجّل لكل موظف في
   شاشة "بصمة (استيراد وتصحيح)" بالباك إند (نفس الكود المستخدم في الاستيراد اليدوي أصلًا).

لو حصل أي مشكلة، محتاج تصحيح فعلي مع الجهاز الحقيقي - ابعت رسالة الخطأ أو شكل السجل الخام وهنظبطها.

## آلية العمل

جهاز البصمة نفسه **مش بيعمل push** لأي حاجة - الـAgent هو اللي بيتصل بيه (TCP/IP، بورت 4370 افتراضيًا)
كل `POLL_INTERVAL_SECONDS` (5 دقايق افتراضيًا) ويسحب سجلات البصمة الخام لآخر `LOOKBACK_DAYS` يوم. كل سجل
خام مجرد "لمسة" (وقت + كود موظف) - الجهاز مش بيفرّق دخول عن خروج، فالـAgent بيجمّع اللمسات لكل موظف/يوم:
**أول لمسة = دخول، آخر لمسة = خروج** (لو لمسة واحدة بس في اليوم، الخروج بيفضل فاضي - يوم بصمة ناقصة زي
أي استيراد يدوي عادي). بعد كده بيبعتها دفعة واحدة لـ`POST /api/attendance-sync/punches` - نفس نقطة
الـupsert اللي الاستيراد اليدوي بيستخدمها (تكرار نفس الموظف/اليوم بيحدّث مش يكرر صف).

ده مش "لحظي" فعليًا (الجهاز نفسه مالوش push) - أقرب حاجة ممكنة هي تقليل `POLL_INTERVAL_SECONDS`، لكن
5 دقايق كافية جدًا للمتابعة الإدارية (حضور/تأخير)، مفيش داعي لأقل من كده.

## التركيب

1. سطّب [Node.js](https://nodejs.org) (نسخة LTS) على جهاز/سيرفر الفرع لو مش مسطّب - لازم يكون على نفس
   شبكة الفرع اللي جهاز البصمة متوصّل عليها (ولو ممكن، بنفس الجهاز اللي شغال عليه print-agent أصلًا).
2. انسخ الفولدر ده (`attendance-agent/`) على جهاز الفرع.
3. من داخل الفولدر:
   ```
   npm install
   ```
4. من شاشة **إدارة المستخدمين** (`satamoni-admin.html`) اعمل حساب دخول مخصص للـAgent - **مدير فرع**
   (branch_manager) خصّص له صلاحية "مزامنة بصمة الفرع من جهاز البصمة" بس (نفس فلسفة حساب الـPrint Agent
   بالظبط - ميتفتحش من متصفح، أضيق صلاحية ممكنة).
5. انسخ `.env.example` لملف اسمه `.env` واملأ:
   - `API_BASE_URL` — رابط سيرفر ستاموني.
   - `AGENT_EMAIL` / `AGENT_PASSWORD` — حساب الـAgent اللي عملته فوق. الفرع بيتحدد أوتوماتيك من الحساب
     لو مدير فرع (زي print-agent بالظبط) - مش محتاج تدوّر على رقم الفرع.
   - `ZK_DEVICE_IP` — عنوان IP بتاع جهاز البصمة على شبكة الفرع (اسأل مسؤول الشبكة عندكم لو مش عارفه).
   - `ZK_DEVICE_PORT` — افتراضيًا 4370 (البورت القياسي لأجهزة ZK - غيّره بس لو الجهاز مظبوط على بورت مختلف).
   - `POLL_INTERVAL_SECONDS` / `LOOKBACK_DAYS` — افتراضياتهم معقولة (300 ثانية / يومين)، عدّلهم لو حابب.
6. تأكد إن كود "User ID" لكل موظف مسجّل على جهاز البصمة نفسه بيتطابق مع `device_code` المسجّل ليه في
   شاشة "بصمة (استيراد وتصحيح)" (`satamoni-payroll.html` تبويب البصمة).
7. شغّل الـAgent:
   ```
   npm start
   ```

## تشغيله دائم (حتى بعد إعادة تشغيل الجهاز)

نفس أسلوب print-agent بالظبط:
- سطّب [pm2](https://pm2.keymetrics.io) (`npm install -g pm2`)، وشغّل
  `pm2 start index.js --name satamoni-attendance-agent` ثم `pm2 save` و`pm2-startup install`.
- أو shortcut لملف `.bat` بيشغّل `npm start` في فولدر "بدء التشغيل" الخاص بويندوز (`shell:startup`).

## استكشاف الأخطاء

- لو ظهر "الجهاز ده مش موجود/مش متجاوب" - تأكد إن جهاز/سيرفر الفرع اللي شغّال عليه الـAgent فعليًا على
  نفس شبكة (VLAN) جهاز البصمة، وإن مفيش Firewall قافل بورت 4370.
- لو البصمات بتتبعت بس مش ظاهرة لموظف معين في تقارير الحضور - راجع إن `device_code` بتاعه في النظام
  مطابق حرفيًا لكود الـUser ID على الجهاز (أرقام زيادة/ناقصة بسبب صفر بادئ زي "01" vs "1" سبب شائع).
- شغّل بـ`DEBUG_RAW_LOG=1` في `.env` لو عايز تشوف شكل السجل الخام من الجهاز نفسه (مفيد جدًا أول مرة).
