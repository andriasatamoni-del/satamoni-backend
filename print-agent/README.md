# Branch Print Agent — ساتاموني

برنامج صغير مستقل بيشتغل على جهاز الفرع (بالطابعة الحرارية موصّلة عليه)، بيسحب أوامر الطباعة من سيرفر
ساتاموني ويطبعها فعليًا على الطابعة - **بشكل صامت تمامًا من غير أي نافذة/print dialog**، وبيفضل شغال حتى
لو المستخدم قفل شاشة الـPOS في المتصفح خالص (عملية Node.js منفصلة تمامًا).

## آلية الطباعة

جرّبنا الأول توليد PDF بمقاس الورق الحراري بالظبط وبعته بمكتبة `pdf-to-printer` (SumatraPDF جوّاها).
اتحقق فعليًا على XP-D200N إن ده بيطبع الإيصالات الطويلة صح، لكن تذاكر المطبخ القصيرة كانت بتطلع منزّحة/
مقطوعة رغم كل محاولات ضبط المقاس - بينما "إعادة طباعة" من متابعة الطلبات في الشاشات القديمة (اللي بتستخدم
`window.print()` من المتصفح مباشرة) كانت بتطبع نفس المحتوى صح تمامًا كل مرة. يبقى المشكلة في مسار
SumatraPDF نفسه، مش في المحتوى ولا الطابعة.

**الحل الحالي:** Puppeteer بيشغّل نسخة Chromium معزولة تمامًا عن أي حاجة تانية على الجهاز، وبيطبع بنفس
آلية `window.print()` بالظبط - المستخدم مايشوفهاش خالص لأن النافذة بتتفتح برّه حدود الشاشة تمامًا،
و`--kiosk-printing` بيمنع ظهور أي نافذة/dialog تأكيد طباعة. فلاج `--kiosk-printing` ده بيطبع على "الطابعة
الافتراضية" في ويندوز بس (مش بيقبل تحديد طابعة لكل طبعة لوحدها) - عشان نقدر نوجّه لأكتر من طابعة (كاشير/
مطبخ/دليفري)، الـAgent بيغيّر الطابعة الافتراضية في ويندوز لحظيًا قبل كل أمر طباعة (عن طريق PowerShell) -
آمن لأن الطابور بيتعالج واحد واحد بالترتيب مش بالتوازي.

## التركيب (على جهاز الفرع - Windows)

1. سطّب [Node.js](https://nodejs.org) (نسخة LTS) لو مش مسطّب.
2. انسخ الفولدر ده (`print-agent/`) على جهاز الفرع.
3. من داخل الفولدر:
   ```
   npm install
   ```
4. انسخ `.env.example` لملف اسمه `.env` واملأ:
   - `API_BASE_URL` — رابط سيرفر ساتاموني (نفس اللي شاشة الكاشير بتستخدمه).
   - `AGENT_EMAIL` / `AGENT_PASSWORD` — حساب دخول حقيقي **مدير فرع** (branch_manager) خصّصه للـAgent
     (ينصح تعمل حساب مخصص للطباعة بس، مش تستخدم حساب شخص بيسجل دخول من المتصفح كمان، عشان الجلستين
     ميتعارضوش). لو الحساب ده مدير فرع، الفرع بيتحدد أوتوماتيك من الحساب نفسه - **مش محتاج تدوّر على رقم
     الفرع**. لو مضطر تستخدم حساب أدمن بدل مدير فرع، لازم تحدد `BRANCH_ID` صراحة في الملف (شيل الـ# من
     قدامها واكتب رقم الفرع).
   - `POLL_INTERVAL_SECONDS` — كل قد إيه (بالثانية) يسأل عن أوامر جديدة (افتراضي 5).
5. من شاشة **إعدادات الطباعة** (`satamoni-printing.html`) سجّل الطابعة/الطابعات المتصلة بالجهاز ده - لازم
   `اسم الطابعة` يتسجل **بالظبط زي ما هو ظاهر في Windows** (لوحة التحكم > الطابعات والماسحات).
6. شغّل الـAgent:
   ```
   npm start
   ```

## تشغيله دائم (حتى بعد إعادة تشغيل الجهاز)

الـAgent عملية طرفية عادية (`node index.js`) - محتاج يفضل شغال في الخلفية. أبسط طريقة:
- سطّب [pm2](https://pm2.keymetrics.io) (`npm install -g pm2`)، وشغّل `pm2 start index.js --name satamoni-print-agent`
  ثم `pm2 save` و`pm2-startup install` عشان يشتغل تلقائي مع فتح الجهاز.
- أو أبسط: اعمل shortcut لملف `.bat` بيشغّل `npm start`، وحطه في فولدر "بدء التشغيل" الخاص بويندوز
  (`shell:startup`).

## استكشاف الأخطاء

- لو الطابعة اتسجّلت بس مفيش طباعة بتحصل: راجع تبويب "طابور الطباعة" في `satamoni-printing.html` -
  الأوامر اللي فشلت بتظهر بسبب واضح (مثلاً اسم الطابعة غلط أو الطابعة مقطوعة).
- الـAgent بيطبع لوج (console) واضح لكل أمر طباعة - شغّله من `cmd`/`PowerShell` مباشرة (مش كـ service)
  أول مرة للتأكد إن كل حاجة شغالة صح قبل ما تخليه يشتغل تلقائي.
- لو الطابعة موصّلة USB، الاسم في `os_printer_name` لازم يتطابق حرفيًا مع الاسم في Windows (بما فيه أي
  رقم/نسخة زي "XP-80C").
- الـAgent بيغيّر "الطابعة الافتراضية" في ويندوز أوتوماتيك قبل كل أمر طباعة (لازم عشان التوجيه لأكتر من
  طابعة يشتغل صح مع `--kiosk-printing`) - ده طبيعي ومتوقّع، مش خطأ. لو حابب تتأكد بنفسك إن PowerShell
  شغال صح على الجهاز، جرّب الأمر ده في PowerShell وشوف مفيش خطأ: `Get-CimInstance -ClassName Win32_Printer`.
